# Swasthya

**Swasthya** is an open-source, location-aware health-intelligence and wellbeing-awareness platform. Its primary purpose is to answer three questions:

1. **What health-relevant thing is happening around me?**
2. **Does it matter right now?**
3. **What can I reasonably do next?**

> Swasthya is an awareness and decision-support product. It does not diagnose, prescribe treatment, identify nearby patients, replace professional medical advice or replace emergency services.

## Live application

**Around Me — vicinity health intelligence:** https://utpal-mishra.github.io/Swasthya/

**My Health — optional personal dashboard:** https://utpal-mishra.github.io/Swasthya/dashboard.html

## Around Me — country-aware health intelligence

The primary page changes its health context when the selected or live location changes, including across country borders.

Current implementation:

- Town/city geocoding with country code
- Browser geolocation with reverse country/region resolution
- Optional **Live Health Awareness** using coarse location-cell changes
- 1–25 km environmental/nearby-service context
- Live current weather and modelled air context
- Dynamic `What Matters Now?` prioritisation
- Country-aware official public-health intelligence
- Local → national → regional → WHO fallback strategy
- Country-specific health-authority links
- Verified emergency numbers for countries included in the provider registry
- Nearby pharmacy, healthcare, essentials and indoor-place searches
- Material-change notifications
- Explicit geographic-precision labels for every public-health item

## Official public-health integration

Swasthya builds a static public-health cache from authoritative sources through a scheduled GitHub Action.

Current connected layers:

- **HPSC wastewater surveillance** — catchment-level SARS-CoV-2 surveillance context for Ireland
- **HPSC Ireland** — national epidemiology/surveillance publications
- **ECDC RSS** — communicable-disease threat reports and epidemiological updates for EU/EEA context
- **WHO Disease Outbreak News (DON)** — global authoritative outbreak fallback

The cache is generated by:

```text
scripts/fetch_public_health.py
        ↓
data/public-health.json
        ↓
Location / country / county matching in app.js
        ↓
Health Around Me
```

The scheduled workflow is:

```text
.github/workflows/update-public-health.yml
```

It runs every six hours, can be triggered manually, and also refreshes after ingestion logic changes are merged to `main`.

### Ireland wastewater proximity layer

The wastewater adapter reads the latest HPSC National SARS-CoV-2 Wastewater Surveillance Programme report and extracts the catchment table when HPSC publishes it in machine-readable HTML.

Each record retains:

- county
- wastewater catchment name
- sample date
- result category such as `Positive`, `Weak Positive` or `Undetectable`
- report publication date
- official source URL
- explicit geographic-precision text

Swasthya then matches the record conservatively to the user's resolved county or named catchment context.

```text
User: Ballincollig, Cork
        ↓
Country: Ireland
County: Cork
        ↓
HPSC wastewater catchment: Ballincollig
        ↓
Named catchment match
```

A positive wastewater sample means SARS-CoV-2 RNA was detected in population-level wastewater surveillance. It does **not** mean an infected individual is at a particular address, that the user was exposed, or that the user is infected.

The user's selected `5 km` or `10 km` radius does not redefine the wastewater-catchment boundary. The UI explicitly says when a signal is a same-county or named-catchment match.

### Geographic honesty

A 5 km user radius does **not** turn country-level disease surveillance into 5 km disease data.

For example:

```text
User location: Cork
Selected radius: 5 km
HPSC signal precision: wastewater catchment / county

Result:
Local wastewater surveillance context
NOT
"patient detected within 5 km"
```

This principle applies to every provider: Swasthya uses the finest geography the source genuinely supports and never manufactures smaller precision.

## Autonomous country switching

The provider selection model is:

```text
Live / selected location
        ↓
Country + region resolution
        ↓
Local official surveillance when supported
        ↓
National source
        ↓
Regional source when relevant
        ↓
WHO fallback
```

For countries without a dedicated connected national or local feed, Swasthya still uses WHO outbreak intelligence and clearly links to the country's configured health authority when available.

`data/country-health-providers.json` contains a growing registry of national health authorities and verified emergency numbers. Unknown countries fall back to WHO without inventing emergency information.

## Environmental health context

The browser currently uses Open-Meteo for modelled weather and European AQI because it does not require a browser-side secret.

Environmental interpretation considers:

- rain / precipitation
- apparent temperature
- cold exposure
- wind
- UV
- European AQI as supporting exposure detail

AQI is deliberately secondary in the citizen-facing experience. Swasthya prioritises the health meaning and recommended action over raw pollutant KPIs.

The secondary page remains optional and includes:

- ADHD support mode

- Stress support
- General mental wellbeing
- Private browser-session check-ins
- Specialist support resources

It does not diagnose, screen or predict a condition.

## Wearable integration direction

A future Android application can optionally read consented Samsung Health data using Samsung Health Data SDK. Useful signals include sleep, heart rate, activity, skin temperature, blood oxygen and Energy Score where available.

Wearable signals should be used for **personal context and trend analysis**, not for claiming that the watch can directly determine emotions such as happy, sad or focused. Any inferred state must be presented as uncertain physiological context and paired with an optional user check-in.

## Privacy principles

- Location access is explicit, optional and revocable.
- When location is used, coordinates are sent to selected weather/air and reverse-geocoding providers to retrieve context.
- The static Swasthya site does not persist exact coordinates in a backend.
- Live awareness refreshes on coarse location-cell changes rather than every GPS movement.
- Individual patient health status is never displayed.
- Future community-health signals must use privacy-preserving aggregation and minimum-participant thresholds.
- Personal wellbeing and wearable data must not be combined with precise location without explicit consent and a deliberate privacy/security architecture.

## Source confidence

Every public-health item should expose:

- provider
- publication date
- direct official URL
- country / regional / local match
- true geographic precision
- source type: local surveillance, outbreak, national surveillance or regional surveillance

**Unknown is better than wrong.** Absence of a matched item does not mean absence of disease.

## Notification limitation

The current GitHub Pages version can show browser notifications while the page is open or active. Reliable background alerts when the site is closed require a service worker, push-subscription storage and a secure backend notification service.
