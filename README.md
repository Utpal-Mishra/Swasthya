# Swasthya

**Swasthya** is an open-source, location-aware health-intelligence and wellbeing-awareness platform. Its primary purpose is to answer three questions:

1. **What health-relevant thing is happening around me?**
2. **Does it matter right now?**
3. **What can I reasonably do next?**

> Swasthya is an awareness and decision-support product. It does not diagnose, prescribe treatment, identify nearby patients, replace professional medical advice or replace emergency services.

## Live application

**Around Me — vicinity health intelligence:** https://utpal-mishra.github.io/Swasthya/

**My Health — optional personal dashboard:** https://utpal-mishra.github.io/Swasthya/dashboard.html

## Around Me — country-aware health intelligence

The primary page now changes its health context when the selected or live location changes, including across country borders.

Current implementation:

- Town/city geocoding with country code
- Browser geolocation with reverse country/region resolution
- Optional **Live Health Awareness** using coarse location-cell changes
- 1–25 km environmental/nearby-service context
- Live current weather and modelled air context
- Dynamic `What Matters Now?` prioritisation
- Country-aware official public-health intelligence
- National → regional → WHO fallback strategy
- Country-specific health-authority links
- Verified emergency numbers for countries included in the provider registry
- Nearby pharmacy, healthcare, essentials and indoor-place searches
- Material-change notifications
- Explicit geographic-precision labels for every public-health item

## Official public-health integration

Swasthya builds a static public-health cache from authoritative sources on a scheduled GitHub Action.

Current connected layers:

- **WHO Disease Outbreak News (DON)** — global authoritative outbreak fallback
- **ECDC RSS** — communicable-disease threat reports and epidemiological updates for EU/EEA context
- **HPSC Ireland** — current Irish epidemiology/surveillance publications

The cache is generated by:

```text
scripts/fetch_public_health.py
        ↓
data/public-health.json
        ↓
Country/region matching in app.js
        ↓
Health Around Me
```

The scheduled workflow is:

```text
.github/workflows/update-public-health.yml
```

It runs every six hours and can also be triggered manually.

### Geographic honesty

A 5 km user radius does **not** turn country-level disease surveillance into 5 km disease data.

For example:

```text
User location: Cork
Selected radius: 5 km
HPSC signal precision: Ireland / report-specific

Result:
National surveillance update
NOT
"case detected within 5 km"
```

If a future official source provides county, municipality, wastewater catchment or other finer geography, Swasthya can use that real precision. Individual patient locations will not be displayed.

## Autonomous country switching

The provider selection model is:

```text
Live / selected location
        ↓
Country + region resolution
        ↓
Country provider registry
        ↓
National source when connected
        ↓
Regional source when relevant
        ↓
WHO fallback
```

For countries without a dedicated connected national feed, Swasthya still uses WHO outbreak intelligence and clearly links to the country's configured health authority when available.

`data/country-health-providers.json` currently includes a growing registry of national health authorities and verified emergency numbers. Unknown countries fall back to WHO without inventing emergency information.

## Environmental health context

The browser currently uses Open-Meteo for modelled weather and European AQI because it does not require a browser-side secret.

Environmental interpretation considers:

- rain / precipitation
- apparent temperature
- cold exposure
- wind
- UV
- European AQI as supporting exposure detail

AQI is deliberately secondary in the citizen-facing experience. Swasthya prioritises the health meaning and recommended action over raw pollutant KPIs.

## Privacy principles

- Location access is explicit, optional and revocable.
- When location is used, coordinates are sent to selected weather/air and reverse-geocoding providers to retrieve context.
- The static Swasthya site does not persist exact coordinates in a backend.
- Live awareness refreshes on coarse location-cell changes rather than every GPS movement.
- Individual patient health status is never displayed.
- Future community-health signals must use privacy-preserving aggregation and minimum-participant thresholds.
- Personal wellbeing data must not be combined with precise location without explicit consent and a deliberate privacy/security architecture.

## Source confidence

Every public-health item should expose:

- provider
- publication date
- direct official URL
- country / regional match
- true geographic precision
- source type: outbreak, national surveillance or regional surveillance

**Unknown is better than wrong.** Absence of a matched item does not mean absence of disease.

## Notification limitation

The current GitHub Pages version can show browser notifications while the page is open or active. Reliable background alerts when the site is closed require a service worker, push-subscription storage and a secure backend notification service.

## Run locally

```bash
python -m http.server 8000
```

Open:

- `http://localhost:8000/`
- `http://localhost:8000/dashboard.html`

To rebuild the public-health cache locally:

```bash
pip install requests beautifulsoup4 feedparser pycountry
python scripts/fetch_public_health.py
```
